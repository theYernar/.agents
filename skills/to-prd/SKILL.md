name: to-prd
description: Convert a rough product idea, feature request, user story, chat notes, or ambiguous product direction into a concise PRD. Use when the user asks for a PRD, product requirements, feature spec, or wants to turn an idea into implementation-ready product scope.
---

Turn the user's input into a practical PRD.

Keep the PRD compact and implementation-oriented. Use this structure:
- Title
- Problem
- Goals
- Non-goals
- Users and use cases
- Requirements
- UX notes
- Edge cases
- Open questions
- Success criteria

Separate confirmed facts from assumptions. Mark assumptions explicitly.

Do not invent complex analytics, rollout, permissions, schemas, or edge cases unless the user's context requires them. Prefer the smallest PRD that would let an engineer or agent start implementation safely.

If the idea is underspecified, ask only the highest-impact questions before drafting, or draft with clear assumptions when the user wants momentum.
